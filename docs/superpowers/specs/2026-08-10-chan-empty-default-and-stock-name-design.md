# 缠论页空默认值与股票名称设计

## 背景

缠论页当前把 `603019.SH` 写死为默认股票。直接访问或刷新 `/chan` 会自动查询该股票，造成页面看起来固定属于某只股票。同时，查询结果标题只显示股票代码，不显示中文名称。

## 目标

- 直接访问 `/chan` 时输入框为空，不自动发起缠论请求。
- 带有 `?ts_code=` 的页面继续自动填充并加载，保留持仓和候选跳转流程。
- 查询成功后显示股票中文名称和标准化代码。
- 名称获取失败时降级为只显示代码，不阻断缠论计算。

## 方案

### 初始状态

`ChanPage` 从 URL 读取 `ts_code`。参数不存在或仅为空白时，`tsCode` 与 `committed` 均初始化为空字符串。React Query 现有的 `enabled: !!committed` 会阻止空页面请求。

空状态在查询卡片下显示简短提示：“请输入股票代码查看缠论结构。”不显示图表、决策卡或错误态。

### 名称数据

后端 `apex.chan.get_structure` 在现有响应中增加 `name` 字段，使用 `data.get_name_map()` 的进程级缓存解析标准化后的 `ts_code`。名称不存在或数据源失败时返回空字符串。

前端 `ChanStructure` 增加 `name: string`。图表卡标题在名称非空时显示“中文名 代码”；名称为空时只显示代码。代码保留等宽次级样式。

不增加单独名称接口，也不从 watchlist 推导名称，因为缠论页支持查询非持仓股票。

## 数据流

```text
/chan
  → ts_code 缺失
  → committed = ""
  → 不请求 API
  → 显示输入提示

/chan?ts_code=603019.SH
  → 自动请求 /api/chan/603019.SH
  → get_structure 标准化代码并从名称缓存取“中科曙光”
  → 响应 name + ts_code
  → 标题显示“中科曙光 603019.SH”
```

## 测试

- 后端结构响应包含中文名称。
- 名称映射缺失时返回空字符串且结构计算不受影响。
- `/chan` 初始页面输入为空，不调用 `getChanStructure`，显示空状态提示。
- URL 带 `ts_code` 时继续自动加载。
- 有名称时显示中文名和代码；空名称时只显示代码。
- 既有缠论后端与前端测试继续通过。

## 非目标

- 不增加股票搜索或中文名联想输入。
- 不修改 URL 查询参数同步行为。
- 不修改缠论算法、周期或决策卡。
