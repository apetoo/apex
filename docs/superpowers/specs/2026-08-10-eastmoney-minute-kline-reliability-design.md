# 东财分钟 K 线可靠性修复设计

## 背景

缠论页的 30 分钟和 60 分钟 K 线仅使用东财 `push2his` 数据源。当前实现通过 Python `urllib` 请求。实际诊断中，同一请求使用 `urllib` 连续收到 `RemoteDisconnected`，改用 `requests` 后立即取得 HTTP 200 和有效 K 线。因此根因是东财边缘服务对当前 `urllib` 连接特征的不稳定拦截，而不是周期参数、股票代码或固定调用次数限制。

当前实现还会把网络、HTTP 和 JSON 异常统一转换为 `None`，导致调用方只能返回模糊的“分钟数据源失败”。分钟线没有备用源，所以单次连接失败会直接使页面不可用。

## 目标

- 让沪深股票的 30 分钟和 60 分钟 K 线稳定使用东财数据。
- 避免本机 HTTP 代理影响国内数据源连接。
- 对瞬时连接错误进行一次有限重试。
- 保留足够的失败信息，区分断连、超时、HTTP 错误、响应解析错误和空数据。
- 限制重复请求，避免触发东财频率或 IP 风控。
- 不改变现有缠论 API、结构计算和前端数据格式。

## 非目标

- 不增加新的分钟 K 线供应商。
- 不支持北交所分钟线。
- 不改变日线、周线的数据源路由。
- 不改变缠论笔、中枢、买卖点或决策卡算法。
- 不进行批量分钟线扫描。

## 方案

### HTTP 客户端

`eastmoney_kline` 改用专用的 `requests.Session`。Session 明确忽略环境代理，使用东财当前有效的 `ut` 参数、浏览器 User-Agent、Referer 和 Accept 请求头。

该改动仅发生在东财 K 线数据源边界。`fetch_raw_bars` 及其上层调用接口保持不变。

### 重试策略

首次发生瞬时连接类异常时重试一次，总尝试次数最多两次。可重试范围仅包括连接断开、连接失败和读取超时。

以下情况不重试：

- HTTP 4xx 参数或权限错误；
- JSON 格式不合法；
- HTTP 成功但 `data.klines` 为空；
- K 线字段无法转换。

重试不扩展为通用重试框架，也不采用多次指数退避，以免放大东财风控风险。

### 缓存与并发

相同股票、周期和请求根数使用短时进程内缓存。缓存仅用于分钟线页面级请求，避免用户切换周期或组件重复渲染时立即重复访问东财。

缓存键必须同时包含股票代码、周期和请求根数，避免重现历史上的不同根数缓存污染。失败结果不进入缓存。

本设计不允许批量并发获取分钟线。

### 错误处理

数据源边界保留具体失败类别供日志诊断，但对既有调用方继续返回 `None`，由 `fetch_raw_bars` 统一转换为 `DataFetchError` 和 HTTP 502，避免改变外部接口契约。

日志不得包含 Token、Cookie 或其他敏感信息。日志内容包括数据源、股票代码、周期、尝试次数和异常类型。

## 数据流

```text
缠论页面
  → /api/chan/{ts_code}?freq=30|60
  → get_structure
  → fetch_raw_bars
  → eastmoney_kline
      → 命中短时缓存：返回 K 线
      → 未命中：requests.Session 直连东财
          → 成功：解析、缓存并返回
          → 瞬时连接异常：重试一次
          → 最终失败：记录具体原因并返回 None
  → 过滤未结束的分钟 K 线
  → 缠论结构与决策卡
```

## 测试设计

测试先行，至少覆盖：

1. Session 不读取环境代理。
2. 有效东财响应被解析为升序 K 线。
3. 首次连接异常、第二次成功时返回有效结果，且恰好请求两次。
4. 连续两次连接异常时返回 `None`。
5. HTTP 4xx、非法 JSON 和空 K 线不发生重试。
6. 相同缓存键命中后不重复请求。
7. 不同股票、周期或请求根数不会错误共享缓存。
8. 失败结果不缓存。
9. 既有日线、周线、分钟未完成区间过滤及缠论测试继续通过。

最后使用真实的 `002648.SZ` 分别请求 30 分钟和 60 分钟数据，验证原始故障路径恢复；真实网络验证不作为自动化测试的一部分。

## 验收标准

- `002648.SZ` 的 30 分钟和 60 分钟请求均返回非空 K 线。
- 模拟首次 `RemoteDisconnected` 时只重试一次并成功恢复。
- 非瞬时错误不被重复请求。
- 缓存键包含股票、周期和请求根数，且失败不缓存。
- 代理环境变量不会改变东财请求的出站方式。
- 缠论后端定向测试全部通过。
- 没有修改前端接口或缠论算法。
