# 筛选策略权重预设设计

## 目标

让不了解策略权重的用户无需逐项调节八个滑杆，也能根据交易风格运行筛选；同时恢复后端已经具备、但当前前端请求始终绕过的自动策略选择能力。

## 交互

筛选页在“策略权重”卡片顶部提供四种互斥模式：

- `自动适配（推荐）`：由后端综合市场 regime、历史表现和当天候选数决定权重。
- `稳健波段`：偏机构资金、回踩均线和主力偷买，关闭高波动追强策略。
- `均衡`：八个策略均有参与，但避免任何单一风格占据绝对权重。
- `进攻趋势`：偏首板、龙头放量和放量突破，降低防御型策略。

自动模式隐藏高级滑杆，并显示自动决策依据说明。三个人工模式展示滑杆；选择预设会用预设值覆盖当前权重，用户随后可以继续微调。手动调整后的模式名称仍保留，表示“基于该预设调整”，不额外增加“自定义”模式。

## 预设权重

所有预设权重之和为 1：

| 策略 | 稳健波段 | 均衡 | 进攻趋势 |
|---|---:|---:|---:|
| first_board_leader | 0 | 0.10 | 0.25 |
| institutional_flow | 0.25 | 0.15 | 0 |
| industry_rotation | 0.10 | 0.15 | 0.15 |
| leader_with_volume | 0 | 0.05 | 0.20 |
| pullback_to_ma | 0.25 | 0.20 | 0.05 |
| bullish_alignment | 0.10 | 0.15 | 0.10 |
| volume_breakout | 0 | 0.10 | 0.25 |
| stealth_accumulation | 0.30 | 0.10 | 0 |

## 数据流

- 自动模式调用 `/api/screener/run` 时不发送 `strategy_weights`，使 `apex.strategy_selector` 接管权重决策。
- 人工模式继续发送当前 `strategy_weights`，后端按现有 manual 分支运行。
- 将用户选择的模式与人工权重一起保存在 localStorage。旧版仅保存权重的数据仍可读取，并迁移为“均衡”人工模式，避免升级后丢失用户设置。
- 日期输入和策略内部阈值不在本次范围内。

## 边界与错误处理

- 后端自动选择失败时，沿用现有等权回退，不在前端复制回退逻辑。
- 默认权重或策略说明尚未加载时，禁用运行按钮。
- 不修改筛选算法、策略评分、体检指标或报告格式。

## 测试

- API 请求测试：自动模式不包含 `strategy_weights`；人工模式包含权重。
- 状态持久化测试：模式与权重可保存和恢复；旧版权重可兼容读取。
- 页面行为测试：默认选中自动模式；选择人工预设后显示滑杆并填入正确权重；切回自动后隐藏滑杆。

## 验收标准

用户首次进入页面看到“自动适配（推荐）”，无需理解权重即可运行；选择任一人工预设后能看到并调整对应权重；后端报告中的 `weights_source` 在自动模式下不再固定为 `manual`。
