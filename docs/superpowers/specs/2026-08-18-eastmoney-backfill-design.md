# 东方财富股吧历史回补设计

## 目标

提供只运行东方财富股吧的受控历史回补命令。调用者必须明确给出业务日期和窗口锚点；默认结果只供审计与展示，不影响影子进度或评分。

## 命令

```bash
python -m apex.eastmoney_guba.backfill \
  --trade-date 2026-08-17 \
  --as-of '2026-08-17T20:00:00+08:00'
```

`--trade-date` 决定产物目录和审计日期。`--as-of` 决定 24 小时加 2 小时重叠窗口，且必须是带时区的 ISO-8601 时间。命令只执行东方财富目标构建、代表成分股选择、采集、标准化导出和审计；不调用 MediaCrawler、不运行 B 站或抖音任务。

## 影子日规则

默认回补的 telemetry 标记为 `backfill`，不会写入正常的 collection run 或增加 14 个合格影子日。

若需人工认可历史回补，可同时使用：

```bash
--count-shadow-day --reason '修复页面结构后的重采'
```

两者必须成对出现。只有当代表成分股完整、解析率、帖子数和独立作者数都满足既有质量阈值时，才允许把该批次记入影子进度；审计会持久化 `backfill`、`count_shadow_day` 与原因。该开关不允许在 promoted 阶段使用。

## 离线重放

`--offline-replay` 读取指定业务日期最近一次保存的 `responses/*.body` 与冻结 manifest，不访问网络；其用途是修复解析器后重导出已有响应。缺少响应、代表成分股目标不足或没有完整审计材料时，命令失败并说明原因，不把部分结果记为合格影子日。

## 安全边界

沿用公开、免登录、低频、请求配额、URL 白名单和作者脱敏。回补不会修改或删除既有批次；每次执行产生独立 batch，最新展示指针仅在成功时更新。
