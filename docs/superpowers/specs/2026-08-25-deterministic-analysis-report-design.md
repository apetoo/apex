# 确定性 AI 分析报告设计

## 背景

LangGraph 分析链路目前把研究轮次中的模型正文持续追加到 `analysis_text`，证据收敛后的草稿阶段却只强制调用 `record_verdict`。最终的 `_final_analysis_text()` 仅能补充判断、置信度、核心证据和交易计划。因此，同一代码路径会因模型在研究阶段是否主动撰写三段式正文而产生不同完整度：600487 得到了完整报告，002192 只得到简版结论。

这不是数据缺失，而是最终报告结构未被程序保证。研究过程还可能包含重复结论、临时计算和自我修正，不应与正式报告混为一体。

## 目标

- 无论研究阶段模型是否输出正文，最终 `analysis_text` 都必须是一份完整、唯一、干净的正式报告。
- 正式报告必须与最终结构化 verdict、置信度、价格建议和仓位一致。
- 研究过程、工具调用与模型自我修正继续完整保存在 trace 中，便于审计和诊断。
- 报告缺失关键章节或与结构化结果冲突时不得静默成功。

## 非目标

- 不改变行情、财务、搜索和证据控制器的数据采集策略。
- 不调整 verdict 档位、置信度规则或交易风控规则。
- 不重做前端报告卡片；前端继续渲染 `analysis_text`。
- 不删除 trace 中的研究过程。

## 方案

采用独立的正式报告生成阶段。研究阶段负责取数、补证和提交研究状态；结构化草稿阶段负责生成并复核 `record_verdict` 或 `record_position_action`；两者通过后，再以最终机器可读结果和已确认的证据上下文生成正式报告。

### 1. 分离研究过程与正式报告

- `reason` 节点仍将 `assistant_text` 事件写入 trace，供进度展示和事后审计。
- 研究阶段的自由文本不再累加到最终 `analysis_text`。
- 最终 journal 中的 `analysis_text` 仅来自正式报告生成阶段。

### 2. 正式报告生成

新增单一职责的报告生成逻辑，输入包括：

- 最终 `draft_kind` 和 `draft_data`；
- 已确认的证据 ledger 和结构化 evidence 摘要；
- 市场环境、技术特征、基本面、历史命中率及玩法数据；
- 研究 thesis、unknowns 和复核结果。

模型必须输出 Markdown 正文，不调用外部工具，不继续搜索。报告必须使用最终结构化结果作为不可修改的事实源，禁止自行更改方向、置信度、价格、仓位或持仓动作。

### 3. 必需章节

未持仓 verdict 报告至少包含：

1. `## 核心判断`
2. `## 基本面分析`
3. `## 一、多头论点`
4. `## 二、空头论点`
5. `## 三、裁判结论`
6. `### 加权四维评分`
7. `### 置信度调整`
8. `## 操作建议`；若结论不支持开多，改为明确的重新评估条件
9. `## 风险提示`

持仓动作报告沿用持仓语义，但同样必须覆盖基本面、多空论据、裁判、评分、动作依据、触发计划和风险提示，且不得把未来条件动作写成当前指令。

### 4. 确定性质量门

增加纯函数校验器，对正式报告执行：

- 必需章节完整性检查；
- verdict、confidence 与结构化结果一致性检查；
- 看多类报告的入场、止损、目标和仓位一致性检查；
- 持仓报告的 action 与关键风控字段一致性检查；
- 禁止过程性措辞，例如“让我查询”“现在提交”“等等，重新核算”；
- 禁止空报告和明显过短报告。

首次生成未通过时，将具体缺失项和冲突项反馈给模型，以温度 0 重试一次。第二次仍未通过时，分析状态返回明确的报告生成失败原因，不把简版模板或研究流水冒充完整报告。

### 5. 独立复核顺序

结构化候选结论先经过现有 reviewer，确保事实和业务规则可靠；正式报告生成后再执行确定性质量门。正式报告不得反向修改已复核的结构化候选，只能准确解释它。

### 6. 前端与存储

- journal 的 `analysis_text` 保存正式报告。
- trace 继续保存所有 `assistant_text`、工具调用、研究状态、草稿和复核事件。
- `VerdictDetailCard` 继续直接渲染 `analysis_text`，无需新增双份正文。
- 如将来需要展示研究过程，可从 trace 提供可展开视图，本次不扩展 UI。

## 错误处理

- 模型或供应商失败：沿用 provider failure 语义，并记录报告生成调用失败。
- 内容校验失败：返回 `report_validation_failed` 及具体 issues，提示重新运行；不得写入伪完整报告。
- 旧 journal 保持兼容，不迁移或重写历史记录。

## 测试策略

采用 TDD，至少覆盖：

- 研究阶段主动输出完整三段式正文时，最终报告仍只使用正式报告生成结果，过程文本不泄漏。
- 研究阶段完全不输出正文时，最终报告仍包含全部必需章节。
- 第一次正式报告缺章节时触发一次定向重试，第二次完整后成功。
- 两次都缺章节时明确失败，不写入简版报告。
- 正式报告 verdict、confidence、价格或仓位与结构化结果不一致时被拒绝。
- 正式报告包含“让我查询”“等等，重新核算”等过程文本时被拒绝。
- 看多、偏空/中性以及 position action 三类路径均保持原有业务字段。
- 运行完整 Python 测试；本次无前端行为变化，但仍运行前端测试、lint 和 production build 作为回归验证。

## 成功标准

- 600487 型路径和 002192 型路径最终都得到相同结构标准的正式报告。
- `analysis_text` 不再包含研究流水、自我对话或多套相互矛盾的最终结论。
- 缺少任一必需章节时分析不会被标记为 completed。
- 结构化 journal 字段、现有证据门控和前端展示保持兼容。
