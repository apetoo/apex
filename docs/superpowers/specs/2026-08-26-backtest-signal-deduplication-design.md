# 回测信号去重设计

## 目标

统一逐笔回测、持有期扫描、模拟聚合和组合回测的信号样本。同一只股票在同一交易日被多次分析时，只模拟当天最后一次判断，避免同一段行情重复计入胜率和平均收益。

## 数据边界

- Journal 继续保持 append-only，不删除或覆盖历史分析记录。
- 回测消费层以 `(ts_code, date)` 作为交易信号唯一键。
- 同一唯一键存在多条记录时，保留 `analyzed_at` 最大的记录。
- `analyzed_at` 缺失时视为最早；若候选记录时间完全相同，保持当前稳定遍历结果，不额外引入随机选择。
- 缺少 `date` 的历史记录无法可靠判断是否重复，继续原样保留。

## 实现方案

复用 `apex.backtest._dedupe_signals()` 作为唯一去重实现。`run()` 不再自行加载并直接模拟未去重的多头记录，而是在预取行情和逐笔模拟前调用该函数。已有的 `load_long_entries()`、`run_sweep()`、`aggregate()` 和 `run_portfolio()` 保持使用同一函数。

不在 `_run_entries()` 内隐式去重：该函数接收调用方已经确定的样本集合，测试和 OOS 切分可能有意传入特定记录。在公开回测入口统一去重，可以保持内部函数职责明确。

## 输出与兼容性

- API 字段和前端类型不变。
- 原始 Journal 条数不变。
- 逐笔列表、CLI 摘要与聚合统计的样本数将减少到统一口径。
- 当前数据预计从 109 条正式结果校正为 105 条，胜率从 43.12% 校正为约 42.86%。这是纠正统计权重，不是策略性能变化。

## 测试

- 先添加回归测试，构造同股同日两次分析且价格建议不同的记录。
- 验证 `run()` 在修改前返回两行，使测试按预期失败。
- 修改后验证只返回一行，并保留 `analyzed_at` 较新的分析及其模拟结果。
- 验证不同股票或不同日期不会被合并。
- 运行回测相关 Python 测试，并用现有 Journal 重算，确认逐笔正式样本数与聚合样本数均为 105。

## 非目标

- 不清理历史 Journal。
- 不合并跨日信号。
- 不修改 AI 提示词、选股条件、止盈止损规则或持有期。
